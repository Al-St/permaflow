# Методика предобработки телеметрии ПНСММ

Рабочее описание алгоритмов пакета `permaflow`. Обоснование выбора методов
(анализ распределений, сравнение законов, испытание на данных 82 пунктов)
приведено в магистерской диссертации (гл. 2).

## 1. Постановка

На вход — таблица сообщений устройств:

```
IMEI | DateTime (UTC) | GNSSLatitude | GNSSLongitude | T1..T32 (0-25 м)
```

Устройства переносят между скважинами, меняют поколения и теряют GNSS
(часть позиционируется по вышкам сотовой связи). Модель сети:

- **кластер** — непрерывный период сообщений одного устройства в одном
  месте;
- **скважина (TB)** — группа кластеров одной скважины;
- **БПН** — базовый пункт наблюдений (реестр `base_stations.csv`).

## 2. Предварительная фильтрация выгрузки

До кластеризации из выгрузки удаляются заведомо некорректные сообщения
(в порядке применения):

1. **зона интереса** — точка сохраняется, если она
   лежит в пределах широт 65–90° **или** восточнее 50° в.д.
   Это нужно, чтобы отбросить заведомо невалидные точки, лежащие
   вне зоны многолетней мерзлоты.
2. **будущие даты** — сообщения позже `max_valid_date` (сбой часов прибора).
3. **ручные исключения** — блок `exclusions` конфигурации.

## 3. Пространственно-временная кластеризация (ST-DBSCAN)

Кластеризация выполняется **раздельно по устройствам**: сообщения разных
IMEI принципиально не попадают в один кластер. Внутри устройства работает
ST-DBSCAN (Birant & Kut, 2007): соседство = пространственная близость
(<= eps_rad) **и** временная (<= eps_t_days).

Параметры по классам точности координат (класс — по «Погрешность координат
в метрах» из `devices.csv`, порог `accuracy_split_m`):

| класс | eps (радианы/метры) | MinPts |
|-------|--------------------|--------|
| GNSS (Marlin) | 9.3e-06 / ~60 м | 120 |
| LBS (КЦТ, РГТ-ИТМ2; вышки, ~85 км) | 0.003 / ~19 км | 13 |

MinPts берётся из реестра устройства, если заполнен (иначе — значение класса
точности). Если сообщений у устройства меньше MinPts, порог ограничивается
числом сообщений; устройство, не набравшее ни одного плотного периода
(например, короткий ряд в десятки сообщений при MinPts 120), остаётся шумом
и в продукт не попадает — пайплайн пишет об этом предупреждение в лог.
Временной радиус (`eps_t_days`, 30 суток) разрывает длинные перерывы
передачи: один и тот же прибор до и после многомесячного перерыва — разные
кластеры.

Реализация: радиальные соседи через `NearestNeighbors` (haversine, радианы)
с последующим временным фильтром; соседство не включает саму точку, поэтому
при проверке ядра она добавляется к числу соседей явно — как в каноническом
DBSCAN, где min_samples считает окрестность вместе с самой точкой. Рост
кластеров из ядер по канону (неплотные непосещённые точки остаются шумом).

## 4. Привязка к БПН и сборка скважин

Кластер привязывается к **ближайшему** БПН из `base_stations.csv`
(координаты с 5 знаками после запятой); кластеры дальше `max_attach_km`
(50 км) помечаются UNIDENTIFIED — в продукт не попадают, но показываются на
карте (красные ромбы) с ближайшим БПН, расстоянием до него и числом
сообщений.

Скважины собираются внутри БПН по правилу **взаимной близости**: кластеры
A и B объединяются, только если d(A, B) <= eps_A **и** d(A, B) <= eps_B, где
eps каждого кластера — радиус по классу точности его устройства. Односторонняя
близость оставляет две разные скважины (пример: GNSS-кластер с eps 60 м и
LBS-облако с eps 19 км у одного пункта — разные скважины). Компоненты
связности графа взаимной близости = скважины; идентификатор
`TB-<код БПН>-<NN>`, нумерация по убыванию числа сообщений.

## 5. Промежуточный продукт: поток сообщений со скважинами

`RES_clustered.csv` — сообщения исходной выгрузки, размещённые по скважинам,
с исходной временной осью (без регуляризации). Колонки:
`well id, DateTime, cluster, GNSSLatitude, GNSSLongitude, T1..T32`.

- `cluster` сохраняется: кластер — период одного устройства на скважине,
  по нему этап фильтрации отбрасывает переходный процесс прибора в начале
  каждого периода и выравнивает ступени при смене поколений;
- IMEI в продукт не входит (идентификатор устройства — не пункт измерений);
  соответствие приборов и скважин фиксируется в `clusters.csv`/`wells.csv`;
- колонки датчиков T1..T32 не переименовываются в глубины: карта глубин
  (0–25 м) применяется при регуляризации — вместе с единой сеткой времени.

## 6. Регуляризация (завершение этапа 1)

Переходный процесс прибора (первые `device_warmup_hours` **часов** каждого
кластера — датчики «выходят на режим») отбрасывается; сообщения осредняются
внутри интервалов единой сетки `default_freq` (6 ч, сроки 00/06/12/18 UTC).
Усреднение применяется только к нескольким сообщениям одного интервала —
одиночные выбросы сохраняются «во весь рост» для этапа фильтрации; пустые
интервалы остаются явными NaN. Колонка `cluster` переносится первым
сообщением интервала. Продукт этапа 1 —
`RES_regularized.csv`: `well id, Date, Time, GNSS, глубины 0–25 м`.

## 7. Фильтрация выбросов и восстановление пропусков (этап 2)

Ряды очищаются от технических артефактов без сглаживания аномалий —
помеченное значение удаляется целиком. Фильтрация раздельна по срокам
наблюдений (суточная волна жива до ~1 м) и по каждой глубине отдельно.

1. **Порог по уровню** — отклонение исходного значения от уровня ряда:
   локальная скользящая медиана (30 суток), медиана всего ряда и серии
   одинаковых значений («залипший» канал). Ловит серийные сбои, которые
   вейвлет-детренд поглощает в аппроксимацию: насыщение датчика на рейке
   +41.9 °C, залипание канала на константе до −60 °C неделями. Пол 25 °C
   отсекает всё физически возможное (реальный синоптический спад на 0.0 м
   не превосходит ~20 °C от уровня месяца).
2. **Скользящий порог Лапласа** (окно 30 суток, MAD-масштаб, квантили α/2)
   по вейвлет-невязке (детренд bior3.1, уровень 1) — аномалии относительно
   локального уровня; окно нечётное, работает на частичных данных, чтобы
   пропуски не отключали фильтр.
3. **Глобальный порог** по всему детрендированному ряду — грубые сбои внутри
   протяжённых «испорченных» эпизодов, когда локальное окно отравлено.
   Порог `min_deviation` (0.1 °C — точность датчиков) не даёт помечать шаги
   квантования на плоских глубоких сериях.
4. **Выравнивание ступеней** при смене поколений приборов (глубины >= 5 м):
   кандидат — только граница кластеров; ступень подтверждается и оценивается
   только на сезон-свободных горизонтах (>= 12 м, годовой ход < 0.2 °C) и
   вычитается единой калибровочной константой на все глубокие горизонты.
   Оценка по мелким горизонтам через пропуски в долю сезона невозможна:
   естественный ход июнь→декабрь на 5 м (+1.4 °C) неотличим от приборной
   ступени. На текущих данных подтверждённых ступеней нет; разность уровней
   поколений на границах кластеров остаётся неопределённой в пределах
   ~±0.5 °C (нужен внешний референс).
5. **Восстановление пропусков**: допустимая длина непрерывного пропуска и
   метод зависят от масштаба изменчивости ряда на глубине. Где жив
   суточный ход (≤ 1 м) — не более 2 интервалов сетки (12 ч), линейно по
   времени: более длинный мост выдумывал бы суточную волну. В зоне
   годового хода без суточного (1–12 м) — до 40 интервалов (10 суток)
   интерполяцией Akima: гладкая кривая следует за сезонным ходом лучше
   прямой. На сезон-свободных горизонтах (≥ 12 м, годовой ход < 0.2 °C) —
   до 120 интервалов (30 суток); мост строится по среднему нескольких
   точек у каждой границы пропуска с линейным ходом между уровнями: у
   границ ряд ступенчат и зашумлён, и прямая между одиночными точками
   переносила бы этот шум на весь мост. Пропуски длиннее лимита своего
   класса и краевые пропуски остаются NaN — их восстановление выходит за
   рамки фильтрации.

Продукт этапа 2 — `RES_clean.csv` (тот же формат, что `RES_regularized.csv`)
и `removal_rates.csv` (доля удалённых значений по скважинам и глубинам, %).

## 8. Отчётные артефакты

| артефакт | содержимое |
|----------|------------|
| `RES_clustered.csv` | поток сообщений, размеченный скважинами (вход этапа 2) |
| `RES_regularized.csv` | регулярные ряды на единой сетке времени (продукт этапа 1) |
| `RES_clean.csv` | очищенные ряды (продукт этапа 2) |
| `removal_rates.csv` | доля удалённых значений по скважинам и глубинам, % |
| `wells_summary.csv` | Base station name, TB id, latitude, longitude, distance to the base station, start date of measurements, number of measurements, number of measurement days, number of missing measurements (in days) — дни измерений считаются по календарным дням с сообщениями |
| `wells.csv` / `clusters.csv` | полная таблица скважин и кластеров (происхождение рядов: IMEI → кластер → скважина) |
| `figures/site_map_interactive.html` | интерактивная карта привязки (plotly): скважины цветом по БПН, БПН — чёрный контур |
| `figures/series_*.png` | примеры рядов «до/после» фильтрации |
